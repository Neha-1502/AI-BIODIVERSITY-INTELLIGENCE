# Darukaa.Earth — Phase 2: Knowledge System

This is the retrievable knowledge layer for the AI Biodiversity Intelligence Chatbot.
It satisfies the brief's "Knowledge System (Critical)" requirement with **two
complementary retrieval paths**, not prompt-only reasoning.

## Structure

```
darukaa-kb/
├── knowledge_base/
│   ├── structured_knowledge.json   # metrics, thresholds, relationship graph, interventions
│   └── corpus/                     # source documents for RAG (replace w/ real report excerpts)
├── scripts/
│   ├── embedder.py                 # TF-IDF embedder (offline-friendly; swappable)
│   ├── build_vector_db.py          # chunks + embeds + indexes corpus into Chroma
│   └── query_kb.py                 # retrieval API: structured match + relationship chain + vector search
├── chroma_store/                   # persisted vector DB (generated by build_vector_db.py)
└── requirements.txt
```

## How retrieval actually works (for your demo/judges)

1. **Structured path** — `structured_knowledge.json` holds:
   - `metrics`: known thresholds per environmental variable (SOC, rainfall, pH, etc.)
   - `relationship_graph`: directed edges connecting metrics (e.g.
     `soil_organic_carbon → microbial_diversity → pollinator_support`) — this is
     what satisfies the "Multi-Metric Reasoning" requirement deterministically,
     not just via LLM guessing.
   - `interventions`: recommendation records with `applicable_conditions`,
     `mechanism`, `impacted_metrics`, `expected_effect`, `time_horizon`,
     `confidence`, and `sources`.

   Given user inputs like `{"soil_organic_carbon": 0.3, "rainfall": 250,
   "land_use_type": "monoculture"}`, `find_matching_interventions()` filters
   interventions whose conditions are satisfied — deterministic, inspectable,
   no hallucination risk.

2. **Vector/RAG path** — corpus documents get chunked (~220 words, 40-word
   overlap), embedded, and stored in a local Chroma DB. For each matched
   intervention, `semantic_search()` retrieves the most relevant supporting
   passages, which you feed to the LLM as grounding evidence + citation source.

3. Both paths combine in `retrieve_full_context(user_inputs)` — this is the
   single function your Phase 3 conversational/reasoning layer should call.

## Setup

```bash
pip install -r requirements.txt
python scripts/build_vector_db.py     # run once, and again after editing corpus/
python scripts/query_kb.py            # sanity check against the brief's example case
```

## IMPORTANT — before your demo

1. **Replace the sample corpus.** The three `.txt` files in `knowledge_base/corpus/`
   are original summary notes written to get the pipeline running — they are
   *not* verbatim excerpts from FAO/IPCC/IPBES publications. For real scientific
   grounding, replace them with actual chunked/extracted text from real PDFs
   (FAO SOC reports, IPCC AR6, IPBES assessments, etc.) using a PDF text
   extractor. Keep the `SOURCE:` / `TOPIC:` header format so metadata tagging
   still works.

2. **Upgrade the embedder if you have internet at the venue.** This sandbox
   couldn't reach huggingface.co, so `embedder.py` uses TF-IDF (scikit-learn,
   fully offline). TF-IDF is keyword-based, not semantic — it will miss
   paraphrased matches. Swap in `sentence-transformers` (`all-MiniLM-L6-v2`) or
   an OpenAI/Anthropic embedding endpoint for real semantic retrieval — the
   `fit_and_save()` / `load()` / `embed()` interface in `embedder.py` is
   designed so nothing else needs to change.

3. **Expand structured_knowledge.json.** Currently has 5 interventions and 8
   relationship edges as a working skeleton. Add more metrics, more
   interventions, and more relationship edges (aim for 15-20+ interventions
   covering all five required categories: soil, land use, biodiversity,
   climate, human impact) before judging.
